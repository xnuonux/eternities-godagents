# Terra architecture field trial v1

## Mission

Design a consequential software system. Make and record a durable architecture decision. Turn these constraints into an implementation-ready technical design.

## Observed problem

Define a provider-neutral host profile and launcher that lets one all-rounder Eternities Godagent consume the certified Godskills release across Codex, Claude Code, and Lunari without replacing shared global instructions or expanding authority.

## Requirements

- Inspect the current `C:\dev\eternities-godagents` and `C:\dev\eternities-godskills` repositories as evidence.
- Compare at least two viable integration approaches on the same dimensions.
- Choose one approach with evidence, consequences, tradeoffs, and revisit triggers.
- Define components, ownership, interfaces, data flow, trust boundaries, failure behavior, recovery, compatibility, and observability.
- Provide a staged implementation handoff and exact verification cases.
- State assumptions, unresolved decisions, and explicit non-goals.
- Make no source changes, network requests, installations, publication, or external actions.

## Output boundary

Write one concise architecture decision and implementation plan to the assigned result path. Cite inspected local files with absolute paths and line numbers where useful. Do not commit.

## Matched-trial controls

- Both subjects use `gpt-5.6-terra` with high reasoning.
- Both receive this exact mission and inspect the same repositories.
- The Godagent subject additionally receives the certified, receipt-bound Godskills method envelope.
- The plain control must not open or use Godskills skill bodies, capability contracts, or the Godagent subject's result.
- Results are compared for requirement coverage, repository grounding, architectural decisiveness, interface and failure precision, verification quality, authority discipline, and concision.
