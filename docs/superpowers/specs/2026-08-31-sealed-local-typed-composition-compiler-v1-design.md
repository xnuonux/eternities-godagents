# Sealed local typed-composition compiler v1 design

## decision

add one explicit optional Godagents factory that composes the certified local
Godskills route and activation process transport with the certified recoverable
typed-composition compiler. it must use the exact pinned Godskills release,
routing executable, activation executable, and typed-composition release.

the factory does not become a default vessel or host path. it grants no new
authority and exposes no provider, credential, Realm, continuity, identity,
keel, evolution, Lunari, Inspiration, or Soul behavior.

## purpose

recoverable typed-composition compiler v1 proves topology-first admission,
activation-bound method compilation, crash reconstruction, and typed execution,
but its route and activation transports are injected assumptions. the sealed
local Godskills transport already proves exact child-process execution and
terminal recovery against pinned executable bytes. this milestone joins those
boundaries so the retained typed mission runs the real local route and
activation binaries instead of fixture transports.

## reusable local transport bundle

factor the already certified local adapter construction into one shared helper
that verifies the routing executable and creates an immutable route and
activation transport pair plus its local execution identity. the existing
local recoverable Godskills adapter must consume this helper without changing
its public behavior.

the helper owns only executable verification and process transport creation.
classification and recoverable binding remain in the calling adapter or typed
compiler. no transport may be accepted from the sealed typed factory caller.

## construction boundary

the sealed typed factory requires:

- one explicit runtime root;
- the exact historical Godskills release pin;
- the exact additive routing executable pin;
- the exact typed-composition release pin;
- one caller-owned activation classifier;
- explicit process and state ceilings, clocks, checkpoints, and lock policies
  when defaults are not sufficient.

construction verifies the executable closure before exposing a compiler. it
derives the local terminal root beneath the compiler's own Godskills state
directory, constructs both process transports, and passes those transports
internally to the recoverable typed compiler. partial configuration and changed
pins fail before child launch.

## public object

the returned object carries a module-private provenance brand and exposes only:

- a closed descriptor binding the compiler protocol and release roots to the
  local routing and activation trust roots and transport descriptors;
- `compileMission`;
- `resumeMission`;
- `execute`.

the underlying transport pair, verified executable object, and private typed
method are not exposed. a lookalike wrapper or compilation from another factory
cannot execute.

## recovery

the retained proof interrupts after the local activation child has atomically
written its result and zero-exit success witness but before process completion
publication. reconstruction verifies the exact executable closure again,
materializes the completion from durable terminal evidence, finishes the
recoverable Godskills binding, compiles the typed method, and executes the
declared Muse-to-Forge graph.

route and activation children each launch exactly once. exact compilation replay
launches no process. topology changes still reject before either child. all
compiler intent and result state remains canonical, bounded, immutable, and
method-body-free.

## deterministic proof

the canary uses a mission whose natural local route is exactly
`eternities-forge` plus `eternities-muse`, while its predeclared topology remains
the same typed Muse-to-Forge graph. it proves:

- executable and composition roots are independently pinned and reported;
- the caller supplies no transport or activation result;
- the exact local router selects the predeclared capability set;
- process death after activation success reconstructs without relaunch;
- route and activation children each launch once;
- the private typed method and terminal output reproduce;
- changed pins, topology, wrappers, and cross-factory handles fail closed;
- no default path, authority, body-disclosure, or identity boundary changes.

## proof limits

v1 still trusts the caller-owned activation classifier, the operating system and
same-user filesystem, and the typed node executors. graph execution remains
in-process and is not journaled per node. the proof does not qualify live model
or skill quality, provider credentials, hostile executor isolation, exactly-once
Realm effects, cross-machine recovery, default host adoption, continuity,
personal-keel writes, identity evolution, Lunari, Inspiration, or Soul.
