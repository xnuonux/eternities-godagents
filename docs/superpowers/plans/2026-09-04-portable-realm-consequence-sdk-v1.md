# portable Realm consequence SDK v1 implementation plan

## scope

Expose the already-certified recoverable Realm consequence host from the
package root. Do not alter default launch, the vessel causal loop, Realm
semantics, Godskills, provider transports, or any historical receipt.

## tasks

1. write the package-root regression first and confirm it fails because the
   protocol and host exports are absent;
2. add the three exact exports and the descriptor protocol declaration;
3. update the closed SDK surface test and add package-root construction,
   exact-retry, descriptor, and authority-boundary assertions;
4. add a deterministic fixture and a source-bound append-only receipt that
   pins the implementation, test, design, plan, prior receipt chain, and
   exact package-root evidence;
5. register the new receipt without changing historical link sets, run the
   focused tests, the complete suite, the certification ledger, and release
   lineage, then inspect the final diff;
6. rebase onto the current canonical main before integration and rerun the
   merged gates.

## acceptance

- package-root tests pass with no provider or external Realm call;
- the fixture proves one mutation and stable terminal retry;
- authority, credential, rollback, default-launch, and continuity limits
  remain false;
- `verify:certifications` reports 53 receipts with the new receipt registered
  and all prior receipts preserving their declared historical links;
- `verify:release-lineage` passes at the merged head;
- no new default or Lunari behavior exists.

## non-goals

- live Realm connectors, remote durability, or external exactly-once effects;
- rollback, compensation, scheduling, delegation, or long-horizon execution;
- SDK exposure of low-level Realm callables or vessel internals;
- default vessel or CLI adoption;
- Godskills, keel, memory, identity evolution, Inspiration, Lunari, or Soul
  integration.
