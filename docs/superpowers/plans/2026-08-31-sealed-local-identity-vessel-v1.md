# sealed local identity-bound vessel v1 implementation plan

## goal

Expose the certified sealed local Godskills route and activation processes as
one explicit identity-bound mission-vessel construction path without changing
the admitted host, legacy CLI, host policy, or any historical receipt.

## task 1: freeze the factory contract

- add failing tests for required runtime root, release pin, routing pin,
  activation root, classifier, native transport, clocks, and lock options;
- require one derived, non-overlapping runtime layout;
- expose only `run`, release identity, and bounded local-execution metadata;
- prove no filesystem path, credential, provider, Realm hand, continuity,
  identity-mutation, evolution, Inspiration, Lunari, or Soul surface escapes.

## task 2: compose the certified layers

- construct `createLocalRecoverableGodskillsAdapter` under the derived
  Godskills root;
- construct `createIdentityBoundMissionVessel` with that exact adapter and the
  derived admission and journal roots;
- preserve distinct mission and Godskills clocks and lock options;
- delegate every routing, activation, binding, mission, and phase semantic to
  the already certified components.

## task 3: prove full-loop recovery

- run the actual Godskills routing and activation entrypoints;
- interrupt after the activation success witness but before completion;
- reconstruct the factory against the same runtime root;
- prove route and activation each launched once;
- complete native generation, deferred review, revision, and final review;
- replay the completed mission and prove zero route, activation,
  classification, native, review, or revision work.

## task 4: certify and integrate

- build one deterministic fixture and append-only certification receipt;
- preserve and verify all twenty-three historical receipts and lineage edges;
- run focused and full suites;
- perform inline adversarial review under the user's no-subagent constraint;
- reconcile origin, fast-forward main, push, verify origin equality, and remove
  only the exact clean feature worktree.

## task 5: reassess admitted-host migration

After this proof, design the smallest explicit host-policy and admitted-runtime
version that can select the sealed vessel without changing historical policy
meaning or pretending live-provider qualification.
