## What changed

The optional native operator now accepts `review` with a separately admitted,
owner-pinned read-only configuration. `captureNativeReviewSnapshot` retains an
explicit set of at most 100 UTF-8 text files/2MiB and references the exact settled
source run. The actual Pi read tool retrieves only those immutable in-memory
bytes. No edit, write, shell, arbitrary file-content backend or personal Grok
keel is exposed. Capture is an owner-selected post-attempt observation, not proof
that the source model authored every byte. This is not an OS sandbox.

`native-review-dispatch.mjs` binds config, request, snapshot, source result and
review response. A locked durable dispatch record is published before launch.
Exact repetition returns recorded results offline. Interrupted final publication
can reconcile an exact terminal native record; absent terminal evidence yields
`review-uncertain`, CLI exit2, without redispatch. Review configurations cannot
bypass that boundary through public `launch` or `resume`.

The deadline starts before review setup. Non-cancellable SDK setup may delay
return but cannot authorize inference after expiry. Every native, retry or
compaction inference reserves the configured response maximum and explicitly
passes that cap in the request options. An observed output overrun or successful
response with unknown output usage denies subsequent tools/inference and final
successful settlement. Original response/usage remain recorded. The host cannot
undo tokens already generated by a provider exceeding its requested cap. This is
reservation plus observed-usage enforcement, not a billing guarantee.

Ordinary configurations remain compatible. No new dependency, agent loop,
global configuration, skill body or trust root was added. The SDK exports are in
`src/sdk/native-pi.mjs`; operator instructions are in
[native-pi-operator.md](../native-pi-operator.md).

## Why this is host review, not deferred Godskills review

The Godskills readiness exchange confirmed that the current default native stack
has no deferred review selection. An availability flag alone does not select a
review. The existing strict historical review-v1 contract also requires separate
reasoning and visible token counters not exposed by the native aggregate report.
Later inspection of this trial's private Pi transcript found a separate SDK
reasoning counter. Thus it is incorrect to claim the underlying provider never
exposes reasoning usage. The existing aggregate and strict historical contract
are not silently changed here; a future adapter must verify their semantics.
`review` and `godskills` cannot be combined in this v1 profile.

Review completion must never serve as automatic code approval.

### Observed budget defect and correction

The final response reported 24,007 output tokens, exceeding the configured
16,384 per-response maximum. Of those, the raw SDK reasoning counter was 22,756.
Across the four responses, SDK reasoning totals 22,839; it is not an additional
quantity to add to the 24,480 output tokens. Pi's installed Responses parser
maps `usage.output_tokens` to `output` and its nested `reasoning_tokens` to the
separate `reasoning` field. [xAI's reasoning documentation](https://docs.x.ai/developers/model-capabilities/text/reasoning)
also documents reasoning usage; raw counter provenance is preserved privately.

An offline actual-Pi regression with a larger catalog cap showed the configured
model limit survived locally. A direct installed Responses transport probe also
serialized `max_output_tokens:16384`. The original live HTTP payload was not
captured, so those probes do **not** establish exactly why that earlier response
exceeded its request allowance. The confirmed host defect was accepting reported
overrun without checking it, not a proven provider or registry failure.

Four failing regressions preceded `25b952f`: absent explicit request option,
continued tools/inference after overrun, successful final settlement after
overrun and continuation after unknown successful output usage. The correction
passed **88/88** focused checks, plus a separate actual-Pi compaction-overrun
check proving no later inference. It does not alter ordinary native sessions or
historical results. The first full suite passed **1,641**, zero failures, nine
existing optional skips at `4bc1139`; a second full release gate is required for
the changed source, not inferred from that earlier pass.
