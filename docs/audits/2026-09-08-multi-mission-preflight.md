## Exact remaining seam

A dependent operator program must bind a prior **committed and accepted** result
to the next mission, not merely receive arbitrary caller prose. Its immutable
program definition must pin templates and backward references before model work.
Actual predecessor completion/artifact digests are unknown at admission time;
they must be resolved and frozen later, without pretending they were predeclared.

Use the template-plus-reference digest as the program step's admitted input
identity, then bind resolved predecessor evidence and the resulting mission
request in a separate exclusive materialization record before execution. Keep
large bodies behind that owned source boundary, not in the generic program
journal. Reject forward/self references, missing/pending/rejected or changed
predecessors, identity mismatch, changed templates, excess projections and
aggregate budgets before the dependent provider operation.

The source must invoke the public authenticated facade and preserve the actual
workflow owner's Realm checks and writer. Calling `executeEffectOnlyIdentity`
directly would skip the required public authentication boundary.

The next prerequisite is now specified: the public facade
has `launch`, not an issued read-only inspection/reconciliation port.
`createResumableMissionReviewKernel().run` can execute a newly absent phase.
Do not label a call to that method as inspection or infer absence from an
unverified missing file. Determine the smallest authenticated operation-state
interface before implementing the program source. The selected
[no-new-inference reconciliation design](../superpowers/specs/2026-09-08-authenticated-reconcile-only-design.md)
reuses authenticated phase materialization and the existing transport's
reconciliation rather than classifying private files. It permits local recovery
writes and is deliberately not called read-only inspection. Ambiguous work must remain
pending; no new retry policy or source-owned duplicate provider journal is wanted.
