# Bounded observation of local Godskills process termination

Status: isolated local implementation complete; full regression run finished with 1,694 passes, one existing external checkout failure, nine skips, and zero cancellations. Not merged or deployed.

A local recoverable Godskills route or activation process previously requested termination at its timeout and then waited indefinitely for the child to emit close. If termination could not be confirmed, releasing the execution lock alone would let a later reconciliation classify unfinished work as absent and launch it again.

The transport now allows a fixed 1,000 ms observation grace after the configured timeout. A kill request returning true, returning false, throwing, or emitting an error does not establish that the child stopped. If close remains unobserved, the transport detaches its event-loop reference, records termination-unconfirmed, and returns the existing pending result. The outbox consequently emits its existing operation-pending error rather than accepting success or dispatching again.

Before spawning, the host publishes process-guard.json, bound to the canonical execution record. The guard survives host death or failure to publish the later termination observation. A fresh transport recognizes the guard and keeps the dispatch pending. Late output and late close/error events do not promote it to success. Invalid guard or observation bindings fail closed. An outstanding guard is never cleared by a success-shaped file: only the host observing a confirmed close removes it. A confirmed exit retains existing success, crash, timeout and explicit retry behavior. Synchronous spawn failure clears the guard because no child was created.

The descriptor, timeout bounds, authority, fixed verified executable, scrubbed environment, shell:false and windowsHide:true remain unchanged. The grace is fixed rather than a new identity-changing option, preserving existing dispatch addresses. The mechanism applies to both stages of the recoverable local transport. The older direct activation adapter and effect-only adapter use separate contracts and are outside this change.

The bound is an observation bound under a responsive Node event loop, plus existing filesystem/lock work. It is not proof that the child or any descendants were killed. Pending uncertainty has no automatic expiry, PID-based clearing or owner replay. There is no new automatic administrative clearance path. All processes sharing this terminal root must use the updated transport; older code does not understand the new guard. Pre-upgrade execution records without a process guard retain their previous behavior; upgrading with old potentially live work needs an explicit migration decision. This fix does not establish exactly-once execution across confirmed-close/output-publication crash windows. Deleting records, changing the operation identity, or starting work with another terminal root is outside this same-dispatch protection.

Source selection came from the existing Jev intake and Luna shortlist. Hermes agent/memory_manager.py:1018-1063 supplies the bounded executor-drain pattern at d1af7e16cbe311570623e4e2e7bbb6489a4346b9 (MIT). Its provider.shutdown call is not itself bounded. This is a local adaptation of the observation principle; no Hermes code or dependency was imported.

Verification so far:
- Untouched runtime plus four new fault cases: original four tests pass; all four new cases fail (two exceeded the watchdog; thrown/emitted kill errors exposed other failure paths).
- Changed transport and outbox: 16 tests pass, including all nine added regressions.
- Cases cover missing close, kill false/throw/error, late output/events, fresh transport and outbox no replay, missing observation with durable guard, malformed guard binding, and confirmed nonzero/timeout/spawn errors with explicit retry.
- Existing tests exercise actual verified local routing and a real local timeout; deliberately missing termination observations use fault injection confined to the test process, without a production executor hook.

An additional adversarial regression demonstrated that the initial guard-plus-success exception could classify a dispatch as absent when given a success-shaped null-result record. That exception was removed. The first broad suite was deliberately interrupted for this correction and is not a completed verification result. The final broad suite runs against the corrected, frozen runtime and tests.

An independent scratch probe replaced only the launcher with an inert real Node child, suppressed its termination request, and used its actual PID and process handle. The lead rerun returned pending in 1,069 ms with the child demonstrably alive, confirmed exactly one launch after fresh reconcile/execute, and explicitly terminated and cleaned up the child. The extended probe then opened the same root and dispatch from a separate Node process while the original child was still alive: both operations stayed pending and restart spawn attempts were zero. The lead confirmed that extended probe in 1,061 ms. This verifies process-observation and persisted restart mechanics; it does not run a Godskills task or establish model quality.

Independent Luna contract/source review found the final guard rule compatible with the outbox and verified the real-child probe. It identified the documented legacy-record and confirmed-close boundaries; no further correctness change is required for the bounded unconfirmed-termination scope. Final full suite: 1,704 total, 1,694 passed, one failed, nine skipped, zero cancelled; 604,526.623 ms with the installed Pi SDK 0.85.1 and four test workers. The sole failure is tests/godskills-specialist-preference-integration.test.mjs:168, which reports "Godskills preference checkout is not current pushed main". This is the known external checkout gate; the release gate is not green. A second broad attempt ended at a session interruption without a completion record; the final completed run used a detached hidden runner and preserved its exit code (1). The known external Godskills preference-checkout gate is not being weakened or repaired in this branch.
