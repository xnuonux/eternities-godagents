# signed OpenAI-compatible phase resolution v1 certification

## disposition

`signed-openai-phase-resolution-v1` is certified as an additive operator
boundary for closing one exact pending OpenAI-compatible phase attempt without
weakening the transport into automatic retry.

It does not replace the existing host, transport, phase contracts, router,
activation executable, Realm boundary, continuity system, personal keel, or
launch defaults.

## certified boundary

One separately canonical JSON policy binds the exact concrete transport policy,
one Ed25519 public key and key identifier, a maximum decision lifetime, and an
adopted-response ceiling no broader than the provider ceiling. Its SHA-256 must
match `GODAGENT_PHASE_RESOLUTION_POLICY_SHA256` before operation inspection.

The private key remains external. A signed decision binds one phase, dispatch,
request, original attempt, disposition, validity interval, nonce, and either
one exact response witness or `null`. The only dispositions are
`adopt-response` and `abandon`.

Adoption reruns the existing strict response parser and phase completion
builder against the exact resupplied response with zero network calls.
Abandonment publishes one sanitized `operator-abandoned` failure and no model
artifact. Neither path can grant retry, provider routing, Realm, continuity,
identity, evolution, Inspiration, Soul, or personal-keel authority.

## execution and recovery proof

`resolution.json` is immutable, body-free, and published before the terminal
completion or failure. A process interruption after that publication can
finish the same accepted decision after its signature window expires. A changed
decision or changed response collides, while an unaccepted expired decision and
an invalid provider response mutate no resolution state.

The deterministic admitted-host fixture makes one native provider call
ambiguous, captures the exact pending operation, adopts one signed recovered
response, and finishes:

`native -> review -> revision -> review`

There is one native provider call total. Exact terminal replay performs zero
provider, routing, or activation work. Durable state contains neither the raw
recovered body nor the credential canary, and the mission expands no authority.

## proof limits

Certification uses a deterministic fake provider and does not establish the
truth or semantic correctness of evidence supplied by an external operator.
It does not prove remote exactly-once execution, query a provider dashboard,
authorize any retry, qualify live model quality, latency, cost, or provider
equivalence, support streaming or tool-bearing responses, migrate a CLI or
default launcher, provide hostile same-user operating-system isolation, or
grant Realm, continuity, keel, evolution, Lunari, Inspiration, or Soul
authority.
